# APPLYING SELECTION CONDITIONS USING THE WHERE CLAUSE

The `WHERE` clause filters rows returned by a query, so you only retrieve records that satisfy a specific condition. Without `WHERE`, every row in the table is returned.

---

## Basic WHERE

```sql
SELECT * FROM grocery_db.customer_details WHERE distance_from_store > 2;
```

**Explanation:** Returns all columns for customers who live more than 2 miles from the store.

**Business use case:** A delivery team wants to identify customers who are far from the store so they can offer targeted delivery promotions or prioritise route planning for long-distance orders.

---

## MULTIPLE CONDITIONS

### AND — both conditions must be true

```sql
SELECT * FROM grocery_db.customer_details
WHERE distance_from_store < 2 AND gender = 'M';
```

**Explanation:** The `AND` operator narrows the result set — a row is only returned when _every_ condition is satisfied. Here, only male customers who live within 2 miles are returned.

**Business use case:** A marketing team wants to run a localised in-store promotion targeted specifically at nearby male customers, for example a campaign tied to a sporting event.

---

### OR — at least one condition must be true

```sql
SELECT * FROM grocery_db.customer_details
WHERE distance_from_store < 2 OR gender = 'M';
```

**Explanation:** The `OR` operator widens the result set — a row is returned when _any_ of the conditions is satisfied. This returns customers who either live close to the store _or_ are male (or both).

**Business use case:** A store manager wants a broad audience for a general awareness campaign and wants to reach customers who are either nearby or belong to a specific demographic segment.

---

## OTHER COMPARISON OPERATORS

| Operator | Meaning                  |
| -------- | ------------------------ |
| `=`      | Equal to                 |
| `<>`     | Not equal to             |
| `>`      | Greater than             |
| `<`      | Less than                |
| `>=`     | Greater than or equal to |
| `<=`     | Less than or equal to    |

```sql
SELECT * FROM grocery_db.campaign_data;
```

### Equal to (`=`)

```sql
SELECT * FROM grocery_db.customer_details
WHERE gender = 'F';
```

**Explanation:** Returns only rows where the column value exactly matches the specified value. The match is case-sensitive in most SQL databases.

**Business use case:** A product team launching a women's health range wants to build a targeted mailing list containing only female customers to improve campaign relevance and reduce wasted spend.

---

### Not equal to (`<>`)

```sql
SELECT * FROM grocery_db.campaign_data
WHERE mailer_type <> 'Mailer1';
```

**Explanation:** `<>` is the standard SQL "not equal to" operator (some databases also accept `!=`). It returns all rows where the column value does **not** match the specified value.

**Business use case:** A campaign analyst wants to review the performance of every mailer format _except_ the control group (`Mailer1`), so they can isolate the uplift generated by the newer variants.

---

### IN — match any value in a list

```sql
SELECT * FROM grocery_db.campaign_data
WHERE mailer_type IN ('Mailer1', 'Mailer2');
```

**Explanation:** `IN` is a shorthand for multiple `OR` equality checks. It returns rows where the column value matches _any_ item in the provided list. This is cleaner and more readable than writing `mailer_type = 'Mailer1' OR mailer_type = 'Mailer2'`.

**Business use case:** The campaigns team wants to measure the response rate for two specific mailer variants so they can compare performance and decide which format to scale up for the next campaign cycle.

---

### LIKE — pattern matching

```sql
SELECT * FROM grocery_db.campaign_data
WHERE mailer_type LIKE '%Mailer%';
```

**Explanation:** `LIKE` allows partial string matching using wildcard characters. `%` represents zero or more characters, so `'%Mailer%'` matches any value that contains the word "Mailer" anywhere in the string (e.g. `Mailer1`, `Mailer2`, `PromoMailer`).

**Business use case:** An analyst wants to pull all campaign records that used any form of physical mailer — regardless of the version number — to compare total direct-mail spend against digital campaign costs.

---

## PRACTICAL EXERCISE

You've been tasked with returning a list of customers who meet the following criteria:

- Live **less than or equal to 0.5 miles** from the store
- Have a value of `'M'` or `'F'` listed for their gender

Your query needs to return: `customer_id`, `distance_from_store`, `gender`

**Business use case:** The store wants to create a hyper-local customer segment — people who live within walking distance — to send a personalised invitation to an in-store event. Filtering by recorded gender ensures the mailing list only includes customers with a confirmed profile entry, avoiding records with missing or invalid data.

```sql
SELECT
    customer_id,
    distance_from_store,
    gender
FROM
    grocery_db.customer_details
WHERE
    distance_from_store <= 0.5
    AND gender IN ('M', 'F');
```
